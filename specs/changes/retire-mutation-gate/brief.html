Retire the built-in mutation gate experiment

TL;DR

The unmerged mutation-gate branch will be deleted because its in-place source editing and evidence model are too risky for a quality gate. Its measured lessons will remain in the repository, and mutation testing will stay on the roadmap through established project-provided tools.

What you'll get

  • No unsafe partial mutation command or unsupported public API on main.
  • A retrospective that prevents future work from repeating the same safety and evidence mistakes.
  • An updated R4 roadmap entry with explicit acceptance constraints.
  • An open-findings list without issues that only applied to the deleted branch.

How it works

No runtime commits are salvaged because the useful tests and helpers are coupled to the unsafe process supervisor. Documentation preserves the evidence; local finding records and branch state are then converged.

What changes for you

There is no new command. If mutation testing is revisited, it starts from a fresh proposal using a recorded external tool rather than this branch.

Risks and open questions

  • Forge still does not mechanically measure whether tests detect broken behavior.
  • The discarded branch may rot, but its reusable conclusions remain documented.

Out of scope

This change does not implement an external mutation-tool adapter and does not resolve unrelated findings discovered during the mutation session.

Work overview

  • Preserve the decision and future constraints: 1 task.
  • Converge findings, session, documentation, and branch state: 2 tasks.
