Honest "done" — turn-end backstop and optional task gates

TL;DR

Today, all of Forge's integrity checks run only when the agent voluntarily runs the closing command — an agent can simply say "done" in chat and nothing stops it. After this change, a lightweight hook catches that moment: if the session claims to be finished but the integrity checks fail, the agent is blocked from ending its turn and told exactly what to fix. Projects that want more can also opt into per-task-group checks. Nothing gets slower by default.

What you'll get

  • An agent can no longer report "done" while deferrals are open, the spine is missing, or the product loop is red — the turn is blocked with the list of problems.
  • Normal work is untouched: mid-session turns with open tasks are never blocked, and the check adds under ~50 ms of file reads per turn.
  • An optional (off by default) gates feature: each task group gets one runnable check, and the coordinator must see it pass before ticking that group's boxes — no more taking a subagent's word for it.
  • Test-run records become tamper-evident: each executed step also stores a digest of its output and where/how it ran.
  • A written rule that session files and command output are data, never instructions (prompt-injection hygiene).

How it works

When the agent tries to end its turn, a small script looks at the active session. If the session isn't claiming completion, the script stays silent. Only when every task is ticked (or the session is in its closing phases) does it run the existing integrity check — and blocks the turn if that check fails. It always errs on the side of letting the turn end if anything about the check itself breaks, and it never blocks twice in a row, so it can't trap anyone in a loop. It can be switched off per project.

What changes for you

  • Re-running forge init --claude on a project adds the new Stop hook alongside the existing hooks (a settings merge, as before).
  • New optional command family: forge gate init / check / status — inert unless you set gates.enabled: true in .forge/config.json.
  • Off-switch for the backstop if you ever want it: hooks.stopGate: "off".

Risks and open questions

  • A hook that blocks turn-end is intrusive if buggy — mitigated by the fail-open design (any internal error = allow), the loop guard, the off-switch, and dedicated tests for each path.
  • The hook's blocking message format follows Claude Code's hook contract; if that contract shifts in a future Claude Code release, the hook degrades to doing nothing (fail-open), not to blocking.

Out of scope

  • Path-ownership claims for parallel workers (recorded as an idea for later — no value for serial sessions).
  • Any approval/permission store for running commands — Forge keeps its interactive trust model.
  • Hooks for agents other than Claude Code (they lack a Stop-hook surface today).
