Fleet should trust the task checklist

Operator brief — change sync-tasks-md-progress

TL;DR

Agents mark work done by checking boxes in the plan’s task list. Fleet and status instead watch a separate counter that agents often forget to update — so a session can look abandoned (0/46, STALE) while half the checklist is done. This change makes the checklist the source of truth for progress and for “is anyone still working?”.

What prompted it

Helm’s phase-3a session showed STALE — idle 11h at implement 0/46 in forge fleet while Claude was actively implementing and 24 of 46 OpenSpec tasks were already checked.

What you'll get

  • Fleet / status / health show checkbox progress from the linked change.
  • Divergent session counters are healed automatically on those reads.
  • Editing the task list counts as activity, so false STALE goes away.

What you won't get

  • No change to how agents implement code or run reviews.
  • The optional --tasks-complete flag stays for subagent bookkeeping; it’s no longer required for progress display.

Work overview

  • Reader — count checked/total boxes in the plan task list.
  • Heal + health — fleet/status/reminder overlay and persist; idle clock uses task-list freshness.
  • Docs — implement guidance says the checklist is authoritative.

How we'll know it's done

  • Unit tests cover count, heal, fleet idle-with-fresh-tasks, and fleet overlay.
  • Re-running fleet against a divergent fixture shows the checklist numbers, not zeros.
