Thorough RE narrowing

Finding F11 · change thorough-re-narrowing

TL;DR

The word contract alone will no longer force thorough pace. Real API / data / OpenAPI contract changes still will — including when a line break sits between the qualifier and the word. The corpus that shipped earlier is what makes this safe to try again after the 0.3.24 revert.

What you'll get

  • Plans that say “the same contract as readLedger” or “must never block work” contract stop escalating to thorough for that word alone.
  • F11's named risky sentences and their hard-wrapped forms still escalate.
  • Finding F11 closed.

How it works

flowchart LR
  T[signal / plan text] --> R[THOROUGH_RE]
  R -->|public/data/OpenAPI + contract| H[thorough]
  R -->|bare contract only| N[not from this arm]
  R -->|money/auth/migration| H
  C[corpus fixture] --> V[CI pin]
  R --> V

Bare contract is dropped. Qualifiers must appear before the noun with flexible whitespace (\s+), so an 80-column wrap cannot disarm the match the way the old single-space rule did.

What changes for you

  • No new commands. forge new / pace suggestion behave as today except for bare-contract false positives.
  • Money, auth, secrets, migrations, Stripe, etc. are unchanged.
