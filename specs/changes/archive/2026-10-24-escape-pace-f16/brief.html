Escape rate by pace, and a sweep label

Operator brief — what this change builds, in plain language.

TL;DR

The Escape rate report will show the rate per pace (thorough, standard, brisk, lite) next to the per-month view, so you can see whether standard-pace process actually leads to fewer escapes than brisk. And when an escape candidate touches a file the change's plan never mentions — the sign that someone else's edit got swept into the change's commit (finding F16) — the listing says so, so you can dismiss it fast.

What you'll get

  • forge escapes report prints a second table: done sessions, escapes, rate and open windows per pace. Sessions with no recorded pace show as unknown.
  • forge escapes marks a candidate with outside plan: <files> — possible sweep (F16) when the files it hit are never named in the change's own plan.
  • Both appear in --json too (byPace, outsidePlan). Nothing existing changes shape.

How it works

Each finished session already records its pace. The report now counts every done session three ways — by month, by pace, and in total. For the label, Forge reads the plan documents the change itself committed (proposal, design, tasks, specs) and checks whether each file a candidate touched is named there.

flowchart LR
  A[later commit rewrites a change line] --> B{file named in the change's plan?}
  B -- yes --> C[candidate, no label]
  B -- no --> D[candidate + 'outside plan — possible sweep']
  C --> E[you confirm or dismiss]
  D --> E

What changes for you

No new commands. The report has one more table; some candidates carry a label. You still decide every candidate yourself — the label never hides one.

Risks and open questions

  • The label is a hint, not proof. On this repo's real history it marks both swept-in files from F16, and wrongly marks one legitimate file out of eleven (docs/usage.md). That is why it labels and never filters.
  • F16 itself stays open: forge checkpoint can still sweep in unrelated edits, because Forge has no record of who edited what. This change only stops those sweeps from costing you more than a quick dismiss.
  • With 11 done sessions so far (9 standard, 2 brisk), the by-pace numbers will be thin for a while.

Out of scope

  • Changing forge checkpoint.
  • Other noise in the candidate list: release commits that rewrite CHANGELOG lines, and commits on the same branch after done. Both get filed as findings.
  • Escape replay eval tasks.
