Turning real escapes into benchmark tasks

TL;DR

Each confirmed escape is a real bug that a Forge session shipped, and each one comes with a test that catches it. This change turns those escapes into eval tasks. An agent starts from the code as it was before the session and gets the session's spec. A hidden copy of the fix's test then decides whether the agent got it right. Forge and a plain agent can then be compared on bugs Forge actually made. This change only builds the task set. Running agents on it costs money and is a separate step that you start yourself.

What you'll get

  • A script, node evals/harbor/export-escape-replays.mjs --project S:/Projects/volo. It writes one task per escaped session that passes the check below. Volo has 47 escaped sessions; the latest export kept 9.
  • The tasks go to evals/harbor/local/, which git ignores. Volo's private code never enters the public forgekit repo.
  • Every task is checked before it is kept. Its test must fail on the code before the session and on the code the session shipped, and it must pass on the shipped code with the fix applied. A task that fails this check is dropped, and export-report.json records the reason.
  • Files like .env are never copied unless you name them with --include.
  • The harness runner accepts --corpus forgekit-escape-replays-v1 once the export exists.

What it won't do

  • It runs no agent trials and builds no Docker images.
  • It skips escapes whose test has no replay rule, and says so in the report.
  • It changes nothing in the published forgekit CLI.

How you'll know it works

CheckExpected
Smoke test on a small made-up projectThe reference solution scores fully shippable. The untouched start scores not functional.
Live export on VoloThe number of kept and dropped tasks, with a reason for each drop.
git status in forgekit after exportNothing under evals/harbor/local/.

Risks

  • For past sessions, Volo commits are linked to a session by timing. A wrong link usually fails the check and is dropped.
  • The Docker setup (installing packages and prefetching the MongoDB binary) is first proven by the first paid run.
  • The live export is slow, because it makes three test runs per session. It runs in the background.
