Init preserves recorded config

Operator brief · change fix-init-preserves-config · finding F125

TL;DR

Re-running the project setup command quietly overwrites choices the project had already made — switching its planning system and turning on a documentation feature it had turned off. Since the latest release note tells people to re-run that command, this misfires on exactly the step users are being told to take. This change makes re-running setup keep what the project already decided.

What you'll get

  • Re-running setup on a project that already chose its planning system leaves that choice alone.
  • A project that turned off the decision-records feature stays off after a re-run.
  • No surprise files appear — the re-run stops scaffolding folders and scripts the project never asked for.
  • You can still change a project on purpose by passing the explicit switch; that always wins.
  • Setting up a brand-new project is completely unchanged.

How it works

Setup decides two things when you don't say otherwise: which planning system to use and whether to keep decision records. Today it decides both from your personal machine defaults, never looking at what this project already wrote down. So a project that chose the lightweight planning system, on a machine whose default is the heavier one, gets silently converted every time setup runs.

The fix adds one source to that decision, ranked above your machine default: the project's own recorded choice. An explicit switch on the command line still beats everything, because typing it is how you ask to change the project.

Risks and open questions

The whole risk is reading "already recorded" correctly. If the code mistakes "no choice recorded yet" for "recorded", a brand-new project could stop honoring your machine default; the reverse would fail to protect a real recorded choice. The tests deliberately check both a project that recorded a choice and one that recorded nothing.

Out of scope

  • No change to what the planning systems are or how they behave — only which one a flagless re-run selects.
  • No change to the explicit switches; they already work correctly.
  • The other open setup bugs (config for concurrent sessions, scaffold wording) are separate changes.
