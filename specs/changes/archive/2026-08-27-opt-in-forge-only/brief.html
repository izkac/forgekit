Opt-in Forge

Operator brief — change opt-in-forge-only

TL;DR

Forge will no longer jump in whenever a request looks like a feature. It starts only when you type /forge or say use Forge. After that, triage is still the first step, so tiny work can skip the ceremony.

What you'll get

  • Plain chat (“add rate limiting”) is implemented directly — no session, no brief, no subagents.
  • /forge … or “Use Forge. …” still runs the full pipeline, starting with triage.
  • An already-open Forge session continues for follow-ups on that work without typing /forge again.
  • Claude Code stops injecting a Forge reminder on every prompt. Session-start reminders for an active session stay.

How it works

flowchart TD
  A[Your message] --> B{Invoked /forge or "use Forge"?}
  B -->|No| C[Do the work directly]
  B -->|Yes| D[Triage]
  D -->|Substantial| E[Forge pipeline]
  D -->|Trivial or skip| C

Already-wired projects keep the old Claude hook until you re-run forge init or forge doctor --install. Agents pick up the new default after forgekit install --skills forge --force.

What changes for you

  • To use Forge, say so. The agent will not start it from a plain feature request.
  • Codex has no slash commands: “use Forge” is the invoke there.
  • /forge:skip still means “this task only, no ceremony.”

Risks and open questions

  • On Windows, Claude Code may keep the old hook file locked until the app restarts. Init deletes it when it can; doctor ignores a leftover copy so it will not nag you to wire it back.
  • Eval arms that already say “use the Forge workflow” still count as an invoke.

Out of scope

  • Removing the forge triage CLI (still there if you run it by hand).
  • Requiring /forge on every turn of an active session.

Work overview

  • Retire the auto-triage hook and clean already-wired projects — 3 tasks
  • Skill, thin rules, operator docs — 2 tasks
