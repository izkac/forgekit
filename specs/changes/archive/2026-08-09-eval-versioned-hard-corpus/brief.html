Preserve v1 and add one genuinely harder evaluation slice

The first authenticated paired trial tied on an easy task. Repeating that task would spend provider budget without improving discrimination. This change keeps every v1 byte and historical result interpretable while adding an explicit, allowlisted companion corpus.

Operator-visible behavior

  • No --corpus flag continues to select frozen forgekit-held-out-v1.
  • --corpus forgekit-hard-v2 selects a separate checked-in task root; paths and unknown IDs fail closed.
  • Plans and trial manifests record corpus, manifest, task, semantic-version, and harness provenance.
  • The first v2 task requires deterministic concurrency, idempotency, expiry, retry, independent-progress, and HTTP behavior across a multi-module service.

Integrity gates

  • CI locks v1 bytes and executable modes.
  • The hard verifier is separate, no-network, UID-dropped, path/symlink hardened, and uses deterministic trusted barriers.
  • Untouched seed fails; reference and structurally different alternate solutions pass; tamper, bootstrap, rewrite, source-forgery, and semantic-mutant evasions fail.
  • Legacy v1 smoke remains six tasks and 18 Docker contexts. Hard-v2 smoke is isolated and validates three contexts.

Claim boundary

This is a one-category hard-v2 foundation, not a completed six-category suite and not evidence that Forge improves model effectiveness. No package is published and no provider is invoked by this change.
