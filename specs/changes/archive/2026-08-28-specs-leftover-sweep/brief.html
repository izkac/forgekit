Specs leftover sweep

Operator brief — change specs-leftover-sweep

TL;DR

Built-in specs projects will get the same leftover check OpenSpec already has: after the work is implemented, the agent searches the whole repo for stragglers (old names, missed files, docs that still describe the old world), fixes them, and only then asks a final reviewer to look at the result.

What you'll get

  • Specs-engine sessions cannot finish until that sweep is done and recorded.
  • The record is a session file with an explicit Remaining: none line — “ready for archive, with notes” is not enough.
  • OpenSpec projects keep using their existing vendor check and file. Nothing about that path changes.
  • Small changes that combine verify and review into one pass still run this sweep first.

How it works

flowchart TD
  A[All tasks done] --> B[Forge verify]
  B --> C{Planning engine?}
  C -->|OpenSpec + vendor skill| D[Vendor leftover sweep]
  C -->|Built-in specs| E[Forge leftover sweep]
  D --> F[Report: Remaining none]
  E --> F
  F --> G[Final review of the post-fix diff]

The agent doing the sweep is the coordinator, not the final reviewer. Reviewers stay inside the session diff on purpose — that is why leftovers used to ship. The sweep is what looks at the rest of the tree.

What changes for you

  • On a specs-engine project, verify will mention the leftover sweep. You do not run a new command.
  • If a session was already in review when this ships, finishing it may need --allow-incomplete or a quick sweep pass.
  • Reinstall the Forge skill after release so agents pick up the new verify steps.

Risks and open questions

  • Every specs session pays for an extra search-and-fix pass, including small ones. That is deliberate: leftovers are how “the task list was complete” still leaves old names in docs and Dockerfiles.
  • The search skips archived changes and old changelog history so it does not turn into busywork. If that skip is too wide, leftovers in those places will still ship.

Out of scope

  • Changing how OpenSpec leftover sweep works.
  • A Forge command that greps the tree for you — the agent still does the search; the CLI only refuses to finish without the report.
  • The review-cadence copy fix (already on the branch, separate from this change).

Work overview

  • CLI gate — refuse review/done without the report (2 tasks)
  • Guard freeze — the report can be written during verify, then locks (1 task)
  • Coordinator skill and verify/apply copy (2 tasks)
  • Product-loop script plus operator docs (2 tasks)
