Four finishing touches for the brainstorm phase

TL;DR

The new round-based brainstorm interview gets four researched extensions: a fast lane for "is this even feasible?" questions, a hand-off document for questions only someone outside the session can answer, a self-test where the agent tries to break its own design before showing it to you, and a vocabulary check against your project glossary that also flags decisions worth a permanent record.

What you'll get

  • Spikes: a feasibility question gets a time-boxed throwaway investigation ending in a recommendation — no spec ceremony. Saying "great" to a spike never starts implementation; real work gets its own brainstorm.
  • Questionnaires: when an answer lives with someone else (a stakeholder, another team), the agent writes a ready-to-send questionnaire-*.md with targeted questions and keeps interviewing you about everything else instead of stalling.
  • Design red-team: before you're asked to approve a spec, the agent invents a few nasty edge-case scenarios and checks the design survives them; anything it can't answer comes back to you as a question, not a surprise in production.
  • Glossary discipline: in projects with a CONTEXT.md, terms that clash with your documented vocabulary get challenged on the spot, and decisions that are hard to reverse, surprising, and genuine trade-offs are tagged ADR-candidate: so your architecture-decision records pick them up automatically.

How it works

All four are additions to the same brainstorming instruction file the previous change rewrote. Classification happens first (spike or normal design flow); the questionnaire and glossary checks run during the interview rounds; the red-team runs during the agent's self-review just before you see the spec. The phase guide learns one new ending: a spike closes the session with its recommendation instead of flowing into planning.

What changes for you

  • Feasibility questions stop producing full specs.
  • You may occasionally be handed a questionnaire file to forward.
  • Specs may arrive with a question like "the design can't handle X — accept or address?" — that's the red-team working.
  • No new commands or settings; projects without a glossary or ADRs notice nothing from the domain pass.

Risks and open questions

  • Instruction-only change: benefits depend on the agent following the text — no mechanical enforcement.
  • Spike misclassification is possible; the guard is that spikes always end in a report to you, never silent implementation.

Out of scope

  • Any CLI/code change (spikes reuse the existing "skipped" session state).
  • Building integration code for ADR tooling — the tag is a text convention.
  • Re-syncing installed skill copies to other machines.

Work overview

  • Add the four extensions to the brainstorming skill (4 tasks).
  • Phase-doc spike ending plus a consistency sweep (1 task).
