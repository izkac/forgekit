A half-read binding must not decide the gate

Finding F27 · change partial-binding-unreadable

TL;DR

Forge decides whether a change was reviewed by someone other than its author by reading what the host recorded about the subagents it ran. When it can only read part of that record, it currently answers anyway — and the answer it gives is "you reviewed your own work", which blocks the change at the money/auth gate. After this change, a record Forge cannot read in full makes it say "I can't tell" and fall back to reading the review file, which never blocks correct work.

What you'll get

  • A session whose review evidence is only half readable no longer gets refused for a review that genuinely happened.
  • Forge stops confusing "this isn't here" with "I couldn't look" — two facts it has been reporting identically.
  • When metrics collection can only read some of a session's history, the numbers it reports say so instead of quietly being a partial total.

How it works

A Forge session is tied to one or more host conversations. That's routine, not exotic — resuming a session adds another one. Forge looks on disk for each conversation's transcript and its folder of subagent records.

Both of those lookups currently treat every kind of failure as "not there". A folder that has been deleted and a folder this process has no permission to open produce the same silent shrug. So if a session is tied to two conversations and the second one can't be opened, Forge answers confidently from the first — and the reviewer who ran in the second is simply invisible.

Today: reviewer ran in the unreadable half → Forge sees no reviewer → verdict is "self-reviewed", stamped as measured fact → forge phase done refuses a change that was properly reviewed.

The fix is to tell the two failures apart:

flowchart TD
    A[Look for this conversation's records] --> B{What went wrong?}
    B -->|Nothing — found them| C[Read them]
    B -->|Not there at all| D[Ordinary: pruned, or nothing was dispatched
Carry on quietly, as today]
    B -->|There, but unreadable| E[Report it]
    E --> F[Evidence answers: I cannot tell]
    F --> G[Fall back to reading the review file]
    G --> H[Correct work is not refused]
    C --> I[Answer from the record]

The distinction matters because "not there" is genuinely ordinary — old transcripts get cleaned up after a few days, and plenty of sessions dispatch no subagents at all. Treating those as "I can't tell" would make Forge unable to answer for most sessions, which is why an earlier, blunter version of this fix was rejected. Splitting the two cases gets the safety without the cost.

What changes for you

  • No new commands and no new flags.
  • forge phase done will occasionally say it could not read the evidence and fell back to the review file. That is the fix working — it replaces a confident wrong answer.
  • Session metrics may note that some of a session's history could not be read. Previously that shortfall was invisible.

Risks and open questions

RiskWhere it stands
A shared internal helper changes shape It has exactly two callers, both in this repo, both updated here. Its existing results keep their exact form.
Forge says "I can't tell" more often than before Only for records that genuinely can't be read — never for ones that were cleaned up. And "I can't tell" falls back to reading the review file, which is the side that cannot refuse correct work.
A deliberately unfixed case If the older half of a session's history was cleaned up rather than blocked, Forge still answers confidently from the surviving half — and a reviewer who ran in the cleaned-up half is still invisible. Fixing that costs the "unable to answer for most sessions" problem above. It stays a named limit in the code, and its real fix is a separate piece of work: stamping the review file itself when Forge dispatches the reviewer, so the proof survives cleanup.
Worth watching: the acceptance test for this change is deliberately inverted — it proves the gate now accepts a case it currently refuses. If it ever starts passing without the fix in place, the fixture has rotted and is proving nothing.

Out of scope

  • The cleaned-up-transcript case described above.
  • Stamping review files at dispatch time (finding F12) — the structural fix several open findings point at, and a change of its own.
  • Any change to how a review file's prose is read. This change only decides when that reading is consulted.
