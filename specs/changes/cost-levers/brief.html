Cutting Forge's cost without cutting its checks

TL;DR

Most of a Forge session's cost is the model re-reading its working context on every step, and the main session carries the most. This change trims what the main session has to carry and avoids wasted work: too many helper agents, and reviewers raising complaints they can't back up. Nothing that protects quality is weakened. No cheaper models, no skipped reviews.

What you'll get

  • A warning when a plan would launch more than 15 helper agents (configurable), with the parts of the plan that add the most. It's never a block.
  • forge status shows how many helper agents the session has used against that budget.
  • Reviewers must back each blocking complaint with proof: a command that fails, the missing requirement and where it's missing, or a concrete scenario at a specific line. Complaints without proof are still reported but no longer force a fix round.
  • Reviewers see the claims already shown to be wrong for this work, so they don't raise them again.
  • One command, forge group close, replaces four separate steps at the end of each task group.
  • A --brief option on forge status and forge phase for short output; the default stays JSON so nothing that reads it breaks.
  • New measurements of how much of the cost is the main session vs its helpers, per task group, so the next round of savings can be aimed with data.

How it works

The plan is checked against the budget once, when implementation starts. During the session the count comes from the dispatch log that already exists. At the end of each task group, one command commits, prepares the review range, checks the evidence and names the reviewer. When a review comes back, a checker splits its complaints into proven and unproven. Only proven ones send work back.

flowchart LR
  P[Plan approved] --> B{Projected helpers over budget?}
  B -- yes --> W[Warning, keep going]
  B -- no --> I[Implement a task group]
  W --> I
  I --> G[forge group close]
  G --> R[Reviewer with known-wrong claims in brief]
  R --> C[forge review-check]
  C -- proven blocking issue --> F[Fix round]
  C -- nothing proven --> N[Next group]
  F --> G

What changes for you

  • Nothing breaks: forge status and forge phase keep their JSON output; --brief is opt-in.
  • An optional budget.subagents setting in .forge/config.json.

Risks and open questions

  • Reviewers might write thin "proof" just to clear the check. The checker requires a specific structure, and refuted claims are still counted, so padding shows up.
  • The running helper count is inflated when two Forge sessions run from the same folder. This was seen today and filed as finding F18. The plan-time warning isn't affected.
  • The "reply in 10 lines" rule for helpers is guidance, not enforced. The new measurements will show whether it holds.

Out of scope

  • Any model, tier or pace change. Brisk pace waits for escape rates by pace (finding filed).
  • Blocking dispatches over budget.
  • Resetting the main session's context between groups.
