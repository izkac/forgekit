Stamp follow-ups

Findings F62, F61, F60 · change stamp-follow-ups

TL;DR

Three small fixes in the same place: how Forge records that a reviewer was dispatched, and how it reads host conversation records for the final-review gate. After this change, a crashed stamp write can no longer silently disable stamping; a duplicated host id can no longer inflate review counts; and a blocked sidecar directory is named in the error (id and path), not just "could not be read".

What you'll get

  • Atomic stamp writes — killing Forge mid-write leaves the previous good stamp file (or a harmless temp sibling), never a truncated live file that refuses every later stamp until manual cleanup.
  • Honest counts on duplicate bindings — if the same host session id appears twice in a session record, Forge measures it once. The money/auth substance floor cannot be flattered by a double-count.
  • Diagnosable readdir failures — when Forge can see a sidecar directory but cannot list it, the stand-aside message names the host session and the path, matching the other blocked-sidecar messages.

How it works

flowchart LR
  A[review-label] --> B[write temp stamp]
  B --> C[rename onto dispatches.json]
  C --> D[census / gate]
  E[host.sessionIds] --> F[findTranscripts dedupe]
  F --> G[reviewEvidence once per id]
  G --> D

Stamp writes go through a sibling temp file, then rename. Host id lists are deduped in the shared locator used by both the review gate and metrics collection. Sidecar list failures keep the existing stand-aside behaviour — only the reason string gains identity.

What changes for you

  • No new commands. forge review-label and forge phase done behave as today when everything is healthy.
  • If a stamp write was previously stuck after a crash, the next successful write works again without deleting files by hand (assuming the live file is still valid, or only a leftover .tmp remains).
  • Blocked-sidecar stand-aside messages become more specific.

Risks and open questions

Money/auth floor. Deduping touches the counts that decide whether a final review had enough substance. That is intentional: today a hand-edited duplicate could inflate those counts. Thorough review applies.
  • Leftover .tmp files after a kill are ignored, not merged.
  • Live sessions created via normal binding already have unique ids; the dedupe residual is hand-edited or merged session.json.
