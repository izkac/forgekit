Add three reviewed hard-v2 evaluation tasks

Hard-v2 currently measures one concurrency bug. Repeating it would spend provider budget without showing whether Forgekit generalizes to different maintenance work. This change adds Security, Tests, and Integration tasks and keeps Feature and Refactor for a later tranche.

How grading remains trustworthy

Each task has protected visible tests and a separate, root-owned, no-network verifier. Candidate code runs under an untrusted UID. Hidden checks use fixed inputs, manual clocks or recording adapters, not source matching or sleeps. A known-good solution and a structurally different correct implementation must both pass. Untouched, tampered, missing-test, and complete semantic-mutant submissions must remain non-shippable.

Product-loop proof

npm run smoke:evals:hard-v2 will select all four manifest tasks, dry-stage baseline and Forge arms, execute every task-specific host matrix, check verifier isolation, and validate three Docker contexts per task. It will report twelve contexts and will not invoke Harbor or a model.

No effectiveness claim. Hard-v2 remains incomplete after this tranche. No provider run occurs during implementation. One baseline/Forge repetition is a paired calibration with order imbalance; exact within-task counterbalancing begins at two repetitions. Any task changed after calibration receives a new version and a new run.

Unchanged

The frozen v1 corpus, default corpus selection, historical results, normalized reward fields, aggregation rules, package publication, and provider configuration do not change.
