Two shipped bugs, nothing else

In one sentence: this fixes a command-injection bug that fires on every prompt you type, and a way to edit a protected test just by changing its capitalisation — and adds no new capability at all.

1. Your prompts were being run through a shell. Two hooks passed whatever you typed to a shell without quoting it. A prompt containing a semicolon or a backtick — an ordinary code snippet, pasted — would have its contents executed. I reproduced it: a prompt ending ; touch /tmp/PWNED created the file. No attacker needed; this was reachable by accident, on every message. The identical bug was found and fixed in a third hook during the last change; its two older siblings were missed.

2. Capitalisation walked past the test guard. The guard blocked src/a.test.mjs but allowed src/A.test.mjs — and on macOS and Windows those are the same file. So an agent could edit a protected test by changing one letter's case. The end-of-session integrity check still caught the change, so this was one layer of two failing rather than a complete hole, but it was the layer that stops the edit happening at all.

What this deliberately does not do

No new features. The previous session added a great deal of new code to a tool whose job is raising quality, and left these two behind. This change is scoped to the two, and I checked a third finding (F88) before starting — it turned out to be already fixed, so it is being closed rather than rebuilt.

One honest limit

The case fix applies only where the filesystem is actually case-insensitive. On Linux, Foo.test.mjs and foo.test.mjs really are two different files, and treating them as one would start guarding files that aren't tracked. The tests drive both behaviours directly so this is verified rather than assumed.
